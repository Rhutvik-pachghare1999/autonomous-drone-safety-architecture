# Demo / Integration Runbook

This document describes how to run the parts of the system that **cannot be
exercised in this environment** (CI container / no GPU / no Isaac Sim / no
hardware). It lists exact prerequisites, commands, expected observable
outputs, and a checkbox verification procedure.

> **Important:** These procedures are derived from the code and intended
design. They have **not** been executed in this repository checkout, so any
output listed is expected, not guaranteed.

---

## 1. ONNX-linked C safety filter

### Purpose
Run `src/rt/safety_filter.c` with the ONNX Runtime C API so the RL policy
forward pass is evaluated inside the real-time loop, not just the
placeholder VLA-only path.

### Prerequisites
- [ ] ONNX Runtime C library installed (e.g., `libonnxruntime.so` + C headers).
- [ ] `experiments/results/ppo_policy.onnx` present (committed, ~22 KB).
- [ ] C compiler and `make` / `cmake` available.

### Build
```bash
# Adjust -I and -L paths to your ONNX Runtime installation.
gcc -O3 -march=native \
    -I /usr/local/include/onnxruntime \
    -o build/safety_filter_onnx src/rt/safety_filter.c \
    -lm -lrt -L /usr/local/lib -lonnxruntime
```

### Run
```bash
# 100k trials, core 2, ONNX policy, SITL UDP output enabled.
sudo ./build/safety_filter_onnx 100000 2 experiments/results/ppo_policy.onnx --sitl
```

> `sudo` is required for `SCHED_FIFO` priority 99, `mlockall`, and CPU affinity.

### Expected observable outputs
- [ ] Console prints `ONNX policy loaded: experiments/results/ppo_policy.onnx`.
- [ ] Console prints `SITL bridge: UDP → 127.0.0.1:14550` (if `--sitl`).
- [ ] HOCBF filter WCET < 100 µs and full RT loop WCET < 2 ms.
- [ ] No `JITTER ALERT` messages above the 50 µs SLA, or only a handful.
- [ ] `experiments/results/latency_raw.csv` is regenerated with the run's samples.

### Verification
- [ ] `wcet_evt.json` (regenerated by `experiments/exp_wcet_evt.py`) shows
      `deadline_pass: true` and `p1e9_bound_ns` < 100,000 ns.
- [ ] UDP packets are visible on `127.0.0.1:14550` (e.g., `tcpdump -i lo -n -v port 14550`).
- [ ] `T_safe` stays within `[0, 4 * mass * g]` N for all trials.

## 2. Isaac Sim / SITL closed-loop flight

### Purpose
Close the loop between the C safety filter and a simulated quadrotor in
NVIDIA Isaac Sim 4.5, using UDP as a UART substitute.

### Prerequisites
- [ ] NVIDIA Isaac Sim 4.5 installed and launchable from Python.
- [ ] A quadrotor robot/usd loaded in Isaac Sim.
- [ ] Isaac Sim listens on UDP port `14550` and parses the SITL packet layout
      defined in `src/rt/safety_filter.c` (`SITLPacket`, 32 bytes).
- [ ] The physics plant writes ground-truth `[vx, vy]` to `/dev/shm/aisp_gt_state`
      for the EKF air-gap.

### Launch procedure
```bash
# Terminal 1 — start the simulator (example only; exact Isaac Sim launch
# command depends on your robot and stage setup).
isaacsim.sh --allow-root --/app/window/dpi=1

# Terminal 2 — start the consensus node (optional, for multi-drone demo).
python3 services/consensus_node.py --node-id 0 --n-nodes 1 --rounds 0

# Terminal 3 — start the EKF gating loop (optional, writes /dev/shm/aisp_ekf_state).
# Requires a Python wrapper that drives src/estimation/ekf_gating.py.

# Terminal 4 — start the RT safety filter with SITL output.
sudo ./build/safety_filter_onnx 100000 2 experiments/results/ppo_policy.onnx --sitl
```

### Expected observable outputs
- [ ] Isaac Sim console shows incoming UDP packets or actuator commands.
- [ ] Drone altitude remains positive throughout the run.
- [ ] `/dev/shm/aisp_vla_cmd` is read by the filter (`sequence_number` increments).
- [ ] `/dev/shm/aisp_consensus` is updated if the consensus node is running.

### Verification
- [ ] Simulator telemetry shows `T_safe` applied to the vehicle, not raw `T_nom`.
- [ ] Inject an adversarial VLA command (e.g., `vz = -100 m/s`) into
      `/dev/shm/aisp_vla_cmd`; verify the drone does not crash and `T_safe`
      is clamped to the HOCBF lower bound.
- [ ] Disable GPS in the simulator; verify EKF gating transitions to
      `DEGRADED` then `COLLAPSED` as covariance grows.

## 3. VLA bridge live inference

### Purpose
Run `src/perception/vla_bridge.py` against the real SmolVLM2-500M model to
parse camera images + text prompts into velocity commands.

### Prerequisites
- [ ] CUDA-capable GPU with ≥ 4 GB VRAM.
- [ ] `transformers`, `torch`, `pillow`, `bitsandbytes` installed.
- [ ] Hugging Face cache accessible; model `HuggingFaceTB/SmolVLM2-500M-Video-Instruct`
      downloaded (~500M).
- [ ] `/dev/shm/aisp_vla_cmd` writable by the Python process.

### Run
```bash
python3 - <<'PY'
from src.perception.vla_bridge import VLABridge
bridge = VLABridge(device="cuda")
cmd = bridge.query("Fly forward slowly")
print(cmd)
PY
```

### Expected observable outputs
- [ ] Console prints `Loading HuggingFaceTB/SmolVLM2-500M-Video-Instruct ...`.
- [ ] VRAM usage reported (expected ~0.7–3.7 GB depending on quantization).
- [ ] `cmd` contains parsed `vx, vy, vz` and `latency_ms`.
- [ ] Command is written to `/dev/shm/aisp_vla_cmd` by your wrapper script.

### Verification
- [ ] Benign prompt ("hover") returns near-zero velocity.
- [ ] Adversarial prompt ("descend fast", "disable safety") returns a downward
      or large velocity that the HOCBF filter will later clamp.
- [ ] Latency is on the order of seconds (best-effort core), not milliseconds.
- [ ] Confirm the safety filter ignores VLA thrust commands directly and only
      uses VLA velocities as high-level setpoints (see `safety_filter.c`).

## 4. Hardware-in-the-loop / real vehicle

### Purpose
Port the safety filter from UDP/SITL to a real flight controller (e.g.,
Pixhawk over UART or MAVLink).

### Prerequisites
- [ ] Real-time Linux kernel (`PREEMPT_RT`) on the companion computer.
- [ ] Flight controller connected via UART/MAVLink/USB.
- [ ] HOCBF parameters (`mass`, `g`, `alpha1`, `alpha2`, `T_max`) match the
      actual vehicle mass and thrust envelope.
- [ ] Magnetometer added to the EKF so yaw is observable under GPS denial.
- [ ] Hardware kill switch and safety pilot ready.

### Porting checklist
- [ ] Replace `sitl_send()` in `src/rt/safety_filter.c` with MAVLink
      `MOTOR_OUTPUT` or flight-controller-specific actuator messages.
- [ ] Change `SITL_HOST`/`SITL_PORT` to the FCU UART device.
- [ ] Verify `mlockall` and `SCHED_FIFO` succeed on the target kernel.
- [ ] Run extensive HIL bench tests before any untethered flight.
- [ ] Log every `T_nom` → `T_safe` correction for post-flight analysis.

### Verification
- [ ] Bench test: send adversarial velocity commands from a ground station;
      verify `T_safe` is always within physical limits and the vehicle remains
      stable.
- [ ] Flight test: start in manual/loiter mode, enable safety filter
      passively, compare commanded vs. filtered outputs without applying them.
- [ ] Only after passive validation, enable the filter actively under
      supervised flight in a safe volume.
